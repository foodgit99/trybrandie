## Problem

The autopilot planner (brand-engine) already classifies each idea with `content_format: "graphic" | "carousel"`, but the runtime that actually generates the content (`supabase/functions/content-autopilot`) ignores this field. Every scheduled idea — including ones explicitly tagged as a carousel — is sent to `design-studio` with `action: "generate"`, producing a single 1080×1080 graphic. So carousels never get generated by autopilot today.

There are also two related bugs once we route to the carousel path:
- `design-studio`'s `generate_carousel` returns `{ slides: [...] }`, **not** `image_url`. The current autopilot code would treat the response as failed.
- `generate_carousel` already inserts one `designs` row per slide (with `carousel_id` + `slide_index`). Autopilot must not double-insert; it should link `content_ideas.design_id` to the first slide and rely on `carousel_id` for grouping.

## Fix Plan

### 1. `supabase/functions/content-autopilot/index.ts` — make `processIdea` carousel-aware

In `processIdea`, branch on `idea.content_format`:

- **`graphic` (or null/undefined)** → current behaviour. No change.
- **`carousel`** → call `design-studio` with:
  - `action: "generate_carousel"`
  - `slide_count: 5` (sensible default; matches the studio's clamp range 2–10)
  - same `brand`, `audience_id`, `trend`, `trend_intensity`, `messages` payload as today
  
  Then handle the response:
  - Expect `designData.slides: Array<{ image_url, slide_index, design_id, copy_structure }>` and `designData.carousel_id`.
  - Skip the manual `designs` insert (slides are already saved by design-studio).
  - Pick the first slide (`slide_index === 0`) as the cover. Update `content_ideas` with:
    - `design_id` = first slide's `design_id`
    - `status: "created"`, `autopilot_status: "completed"`
  - Use the cover slide's `image_url` for the email notification (subject/body unchanged; optionally append "(carousel, N slides)" to the title for clarity).

- Keep the existing 402 / no-credits and generic error handling. The carousel pre-check inside `design-studio` already returns 402 with a clear message when the user can't afford it, so the same `failed_no_credits` branch applies.

### 2. Logging

Add a one-line log at the top of `processIdea` indicating which format is being run (`[autopilot] idea {id} format=carousel slides=5`) so admin traces show carousel runs.

### 3. Out of scope (intentionally)

- Pricing: design-studio already deducts `floor(slides * 1.5)` credits for carousels. No change needed.
- `autopilot-retry`: it just flips `failed_error` → `pending`; format-agnostic, no change.
- `brand-engine` planner: already emits correct `content_format`, no change.
- UI: ContentHub already renders carousels via `idea.content_format === "carousel"` and the existing carousel viewer; no UI change needed.
- Slide count personalisation (per-brand default, per-idea override) — can be a follow-up if you want; for now we hard-code the default to 5.

### Files touched

- `supabase/functions/content-autopilot/index.ts` (only file)

## Acceptance

- An autopilot idea with `content_format = "carousel"` produces a 5-slide carousel saved under one `carousel_id`, with `content_ideas.design_id` pointing at the cover slide and `autopilot_status = "completed"`.
- Graphic ideas still produce a single image as before.
- Out-of-credits on a carousel marks the idea `failed_no_credits` and triggers the existing email; it is retried on the next cycle once credits are topped up.
